# راهنمای کامل تمشک شوتر (قدم‌به‌قدم، برای مبتدی)

## ۱) نصب و اجرا در یونیتی (۲۰۲۱٫۳ تا یونیتی ۶)
1. یونیتی ۲۰۲۱٫۳ LTS یا **یونیتی ۶ (6000.0.50f1)** با ماژول **Windows Build Support (Mono)** نصب کنید.
2. Unity Hub ← Add ← Add project from disk ← همین پوشه. اولین بار چند دقیقه ایمپورت می‌کند (پکیج `com.berry.sdk` داخل پروژه است).
3. اگر یونیتی پرسید «Enable new Input System؟» یا «Switch to ...»، **No** بزنید.
4. منوی بالا: **Berry Shooter ← 2. Create the full main scene (arena, light, camera, game object)** ← Build. این کار **صحنهٔ فیزیکیِ کامل** می‌سازد: کف، دیوارها، ۹ بلوک سنگر، شبکهٔ کف، ۸ نقطهٔ اسپاون، نور، دوربین و شیء بازی (در Hierarchy همه را می‌بینید).
5. **Play** بزنید. اگر کلیدها کار نکردند: `Edit ← Project Settings ← Player ← Other Settings ← Active Input Handling = Both`.
6. فارسی: متن‌ها خودکار شکل می‌گیرند. اگر حروف جدا یا مربع دیدید، فایل فونت (مثلاً Vazirmatn-Regular.ttf) را با نام **`fa-font.ttf`** در `Assets/BerryShooter/Resources` بگذارید.

هشدارهای Unity 6 (FindObjectOfType، SetIconsForTargetGroup، فیلد بی‌استفاده) برطرف شده‌اند. اگر هشدار تازه‌ای دیدید متنش را بفرستید.

## ۲) چطور روی بری تست کنم؟
**الف) داخل ادیتور (بدون لانچر):** Play بزنید ← حالت mock با داده‌ی ساختگی. نام هر نسخه یکتاست (`player-1234`)، پس دو نسخه «Tester» تکراری نمی‌شوند. در تب «لانچر» می‌بینید لانچر باز است یا نه.

**ب) به‌عنوان بازی واقعی بری (روم آزاد، بدون تأیید ادمین):**
1. منوی **Berry Shooter ← 3. Build Windows** ← خروجی در `Builds\BerryShooter` (فایل `berry-game.json` کنار exe کپی می‌شود).
2. لانچر بری را باز کنید و وارد حساب شوید.
3. یک **روم آزاد** بسازید و exe را انتخاب کنید (یا «افزودن بازی دلخواه»). هستهٔ بری `berry-game.json` کنار exe را می‌خواند و برای بازی **نشست SDK** با مجوزهای همان فایل می‌سازد.
4. دوست/سیستم دوم در همان روم وارد شود؛ هر دو «شروع بازی» بزنند. لانچر برای میزبان `-host` و برای مهمان `-connect IP:7777` می‌دهد.
5. در بازی ← منوی اصلی ← تب «لانچر»: باید بنویسد «لانچر باز است: بله» و «این بازی نشست SDK دارد: بله». تب «اتاق» نام و کد و نوع اتاق را نشان می‌دهد.

**اگر نوشت «لانچر باز است ولی نشست SDK ندارد» / «روم درکار نیست»:** فایل `berry-game.json` کنار exe نیست یا خراب است، یا بازی را با دابل‌کلیک باز کرده‌اید. بازی را از لانچر اجرا کنید.

## ۳) بازی از داخل بازی یا از داخل لانچر؟
| روش | چطور |
|---|---|
| **از لانچر** | وارد روم (لیست یا آزاد) شوید ← «شروع بازی». بازی خودش به میزبان وصل می‌شود یا میزبان می‌شود. هیچ دکمه‌ای در بازی لازم نیست. |
| **از داخل بازی: لیست روم‌ها** | منوی اصلی ← «لیست اتاق‌ها» ← روی اتاق بزنید ← لانچر تأیید می‌گیرد ← بازی وصل می‌شود. |
| **با کد اتاق** | «ورود با کد اتاق». |
| **ساخت اتاق از داخل بازی** | «ساخت اتاق بری» ← نام، تعداد (۲ تا ۸)، رمز (اختیاری)، عمومی/خصوصی ← لانچر تأیید می‌گیرد. |
| **با IP** | «اتصال با نشانی IP» (آدرس شبکهٔ مجازی بری مثل `10.77.0.2` یا LAN). |
| **تک‌نفره** | «بازی تک‌نفره». |

## ۴) تست بازی با دو نفر
1. سیستم ۱: روم بسازید و بازی را شروع کنید (میزبان). در لابی دو لیست می‌بینید: «در اتاق بری» (همه‌ی اعضای روم) و «واردشده‌ها به بازی» (کسانی که واقعاً وصل شده‌اند).
2. سیستم ۲: وارد همان روم شود (از لانچر یا از لیست روم‌های بازی). بعد از چند ثانیه در لیست دوم ظاهر می‌شود.
3. میزبان «شروع مسابقه» می‌زند. روی نام هر بازیکن کلیک کنید تا جزئیاتش دیده شود (نقش، ادمین اول/دوم، تیک، کشور، اشتراک و انقضا، پینگ و تأخیر، جیتر، گمشدگی).
4. تنظیمات ← «پروتکل شبکه»: Auto / UDP / TCP را امتحان کنید. HUD بالا-راست پروتکل فعال و پینگ بازی و پینگ بری را نشان می‌دهد.

## ۵) اضافه کردن بازی به «روم» (برای بازی‌ساز)
1. فایل `berry-game.json` را کنار exe بگذارید: `id` یکتا، `executable`، `maxPlayers`، `gamePort`، `protocol` (`udp` / `tcp` / `both`)، `connect`، `hostArgs`، `joinArgs` و `sdk.permissions`.
2. بازی باید آرگومان‌ها را بخواند: `-host` و `-connect IP:PORT` (در این پروژه آماده است: `GameApp.TryAutoStart`).
3. برای نمایش در لیست روم‌های لانچر، بازی باید در **فهرست بازی‌های بری** ثبت و تأیید شود (بخش ۶). بازی‌های دلخواه (custom) فقط در روم آزاد دیده می‌شوند.
4. از داخل بازی هم می‌توان روم ساخت (`Berry.HostLanAsync`)؛ مجوز `lan` لازم است.

## ۶) ثبت در وبسایت (فهرست بازی‌ها، حمایت و پشتیبانی)
**چیزهایی که باید آماده کنید (الزامی برای بری):**
| مورد | مقدار برای تمشک شوتر |
|---|---|
| شناسهٔ یکتا (`id`) | `berry-shooter` (حروف کوچک، عدد، خط تیره، ۳ تا ۴۰ نویسه) |
| نام نمایشی | Berry Shooter |
| نسخه | `1.1.0` (بزرگ‌تر از نسخهٔ منتشرشده؛ قالب `x.y.z`) |
| فایل اجرایی | `BerryShooter.exe` (فقط نام فایل، بدون پوشه) |
| پلتفرم | Windows 10/11 x64 |
| تعداد بازیکن | ۲ تا ۸ (تک‌نفره هم دارد) |
| درگاه بازی | `7777` |
| پروتکل | `both` (UDP + TCP) |
| روش اتصال (`connect`) | `lan`، `vlan`، `wireguard`، `ip` |
| آرگومان‌ها | میزبان: `-host` — مهمان: `-connect {host}:{port}` |
| مجوزهای SDK | `identity, room, players, presence, achievements, scores, token, network, lan, friends, profile` (فقط آنچه لازم دارید بخواهید) |
| بسته | zip با آدرس **https** + مقدار **SHA-256** (`node sdk/node/berry-dev.mjs sha256 BerryShooter.zip`) |
| مسیر انتشار | پلتفرم توسعه‌دهنده: داشبورد سایت ← ثبت بازی ← «کد بازی» و «شمارهٔ بازی» ← انتشار نسخه (`berry-dev release ...`) ← تأیید مالک |
| قیمت | تومان (۰ = رایگان) |

**چیزهایی که تیم/مالک روی سایت وارد می‌کند و شما باید بدهید:** عکس کاور و اسکرین‌شات‌ها، توضیح و راهنمای کوتاه، ویدیو (اختیاری)، دسته‌بندی، راه پشتیبانی (مثلاً صفحهٔ Issues در GitHub یا ایمیل)، یادداشت تغییرات (`CHANGELOG.md`).

**مشخصات فنی دقیق این بازی:**
- موتور: Unity (ساخته‌شده با ۲۰۲۱٫۳ تا ۶٫۰)، رندر Built-in با شیدر اختصاصی (در URP/HDRP هم نمایش می‌دهد)، اسکریپت Mono.
- شبیه‌سازی: میزبان‌محور، ۳۰ هرتز؛ ارسال وضعیت ۲۰ بار در ثانیه؛ پیش‌بینی حرکت در مهمان.
- شبکه: پروتکل متنی نسخهٔ ۲؛ UDP (بسته ≤ ۱۲۰۰ بایت) و TCP (هر پیام یک خط)؛ ترافیک معمول چند ده کیلوبایت بر ثانیه.
- ورودی: ماوس + کیبورد (Input Manager قدیمی یا Both).
- زبان رابط: فارسی و انگلیسی. صدا: تولید‌شده با کد (بدون فایل صوتی).
- حجم: بیلد کوچک است (فقط کد و یک شیدر)؛ **حجم دقیق را بعد از بیلد خودتان از پوشه Builds بخوانید** (من در محیط ساخت نمی‌توانم بیلد بگیرم).
- حداقل سیستم: هر سیستم ویندوز ۱۰ با DirectX 11. (تست روی سخت‌افزار واقعی انجام نشده.)

**امنیت:** برای جزئیات `docs/sdk/SECURITY.md` در مخزن اصلی بری را ببینید. خلاصه: SDK فقط به `127.0.0.1` وصل می‌شود، رمز یک‌بارمصرف دارد، هر کاری که روم/دوستان را تغییر بدهد از بازیکن تأیید می‌گیرد، هش رمز روم و ایمیل/کیف پول/IP واقعی هرگز به بازی داده نمی‌شود.

## ۷) رفع اشکال‌های رایج
| مشکل | علت و راه حل |
|---|---|
| «روم درکار نیست» در روم آزاد | نشست SDK نبود. `berry-game.json` کنار exe بگذارید و بازی را از لانچر اجرا کنید (بخش ۲-ب). |
| مکعب/کپسول نصفه یا تیر دیده نمی‌شود | رفع شد: شیدر اختصاصی `BSFlat` + گلوله‌ی قابل‌دیدن. اگر هنوز بود، لاگ کنسول را بفرستید. |
| صفحهٔ سیاه برای مهمان | رفع شد: مهمان تا اولین وضعیت میزبان صبر می‌کند و دوربین هیچ‌وقت داخل سنگر نمی‌ماند. |
| نام هر دو بازیکن Tester | رفع شد: نام آزمایشی `player-<عدد>`؛ میزبان نام تکراری را شماره می‌زند. در تنظیمات می‌توانید نام بدهید. |
| «لانچر باز نیست» ولی باز است | رفع شد: وضعیت از خود هسته خوانده می‌شود (حتی بدون نشست). |
| فارسی جدا/وارونه | فایل `fa-font.ttf` را در Resources بگذارید (بخش ۱-۶). |
